## 问题与复现

期望：使用现代 Xposed API 100，并产出可下载 APK。

实际：版本目录依赖 API 102，`module.prop` 声明最低 101、目标 102；入口使用 `onPackageReady`，拦截器使用 API 102 Chain/ExceptionMode。

1. 在基线上运行新增的 `python scripts/verify_api100.py`。
2. 首个断言失败，实际属性为 `minApiVersion=101, targetApiVersion=102, autoHotReload=true`。
3. 核对 Maven Central 元数据，发布版本为 101.0.0、101.0.1、102.0.0，没有 100.0.0；单改依赖版本不能解决问题。

本机 Windows 基线构建尝试 `gradlew.bat --no-daemon :app:assembleDebug`。Gradle 9.4.1 与 JDK 21 已下载，但 Foojay 1.0.0 插件解析失败，且本机没有可用 Android SDK。该失败属于本地构建环境证据，不是迁移后的编译结论。

## 修复方案

比较逐个重写 Hook 与引入集中适配层后，采用后者，减少耳机业务改动和回归范围。

- 复用 librepods 固定 API 100 源码模块，保留来源提交与 Apache 2.0 许可。
- 应用仅 `compileOnly` 使用；JVM 测试独立加入测试依赖。
- 改为 API 100 入口构造函数、`onPackageLoaded`、`getApplicationInfo` 与四参数日志接口。
- 集中适配静态 `Hooker.before`、`invokeOrigin`、返回短路和保护性异常处理。
- 设置最低/目标 API 100，移除 API 102 热重载配置。
- 新增 GitHub Actions：安装 SDK、构建 Debug APK、单测、APK 契约检查、上传产物。
- 新建仓库专用 Deploy Key，本地忽略私钥和公钥。用户提交 GitHub 表单后，页面显示 Read/write、指纹匹配，SSH 与 push dry-run 验证成功。

API 100 `invokeOrigin` 绕过其他模块对同方法的 Hook，不能声称与 API 102 链式调用完全等价。该共存差异和运行时验证要求见 `../BUILD_API100.md`。

## 安装反馈与模块介绍修复

用户反馈 API 100 APK 安装正常，但 Xposed 模块详情显示“(未提供介绍)”。检查确认清单没有 `application android:description`；现代 Xposed 从该标准字段读取介绍，而非应用内关于页面的文字。

为 application 增加 `android:description="@string/module_description"`，资源内容为 `OPPO欧真加无线耳机适配Xposed模块`。此项仅为展示资源修改，通过 XML 引用与字符串检查、APK 构建验证，不新增镜像实现的单元测试。

依据：[LSPosed 现代 API 文档](https://github.com/LSPosed/LSPosed/wiki/Develop-Xposed-Modules-Using-Modern-Xposed-API/a7f346f7ec01ea698e1b187fc20de5fc727b0d09)。

安装新版 APK 后重新打开 Xposed 管理器，进入 MelodyLink 模块详情，预期介绍为上述完整文字。用户确认的安装正常不等同于全部耳机功能或多模块共存已验收。
